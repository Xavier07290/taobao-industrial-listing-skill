# V1.2 通用工业品生产工作流

本文件定义每个产品的实际执行顺序。质量优先：先建立事实和设计蓝图，再做单张样图审核，之后逐张生产。不得跳过素材识别或直接让图像模型一次性输出拼版。

## 0. 建立项目目录

每个商品使用独立输出目录，例如 outputs/HS-T/。保留用户原始文件，不覆盖或重命名原始产品照片。所有生成图、透明产品层、背景、设计蓝图和导出文件都放入该商品目录。

建议子目录：
- source/：原始产品图、参数表、竞品图（只读）
- working/：产品抠图、AI背景、细节裁切和临时图层
- final/：最终主图、白底图、详情屏和长图
- qa/：事实表、设计蓝图和质检报告

## 1. 输入素材审查

为每个输入文件标记角色：
- PRODUCT_SOURCE：当前商品真实产品图；
- MANUFACTURER_FACT：厂家参数、说明书、Excel、铭牌；
- COMPETITOR_REFERENCE：同类竞品图；
- STYLE_REFERENCE：用户认可的风格样例；
- STORE_RULE：用户确认的品牌、物流、售后、价格和店铺要求。

如果无法区分某张图的角色，先询问，不要自行把竞品图当成产品原图。记录缺失角度和低清图片。

## 2. 建立事实表

输出 product_facts.md。每个字段至少包含：字段名、数值、单位、适用型号/规格、来源文件及位置、状态（VERIFIED/VISIBLE/UNVERIFIED）。

可见结构只描述肉眼可见外观，不推导内部制动器、齿轮、材质等级或性能。规格列表必须区分标准配置、选配和暂未确认。

## 3. 竞品版式解析

用户要求高度参考竞品版式时，不能只总结卖点。逐张记录以下信息：

1. 画布比例、页边距、分区数量和阅读路径；
2. 标题、副标题、标签、卖点、参数和服务信息的位置；
3. 产品主体的相对位置、方向、占比和视觉重心；
4. 图片/文字/表格的相对面积和信息密度；
5. 背景、光线、色彩、字体粗细和强调色使用；
6. 局部特写、图标、规格表、场景模块如何组合；
7. 竞品图针对买家哪个问题提供答案。

使用0–1000的归一化坐标记录每个模块的 x、y、width、height。形成 competitor_analysis.md，包含“参考图编号、采用的版式特征、替换后的本商品内容、不能沿用的竞品事实/素材”。

高参考度意味着保留通用版式结构和信息层级，不意味着复制对方品牌、完整文案、产品像素或专有插画。

用户选择“高度参考竞品”时，按 SKILL.md 的 REFERENCE LAYOUT LOCK 锁定逐图参考编号、整体构图、产品占比、背景明暗关系、标题位置与产品视觉重心，写入 competitor_analysis.md 和 design_master.md。融合式广告不可擅自改成左右分栏海报，默认风格和模板不得覆盖锁定结构。

## 4. 设计蓝图

输出 design_master.md，必须在生成前完成。蓝图至少包括：
- 产品锁定清单；
- 事实表摘要；
- 参考图与目标图映射；
- 色彩、字体、背景、卡片、边框和标签规则；
- 五张主图的构图与相对坐标；
- 八屏详情页的信息结构；
- 每个文字元素的准确文案与证据状态；
- 每个图层的来源路径；
- 当前审核状态和待确认事项。

## 5. 产品图层准备

真实产品图作为不可重绘的独立图层：
1. 选择清晰、角度合适的原图；
2. 使用可靠的抠图/蒙版工具制作透明PNG；
3. 检查吊钩、链条、铭牌、螺丝、按钮、接口和轮廓边缘；
4. 如抠图破坏细节，回退原图，改用原背景或人工蒙版；
5. 保留原始像素比例，不做非等比拉伸；
6. 局部特写直接从真实原图裁切，不让模型生成内部结构。

## 6. 背景与场景生成

图像模型只生成不带文字、不带品牌、不带产品主体的背景或场景。背景提示词明确写明：不要出现任何机器、吊钩、链条、Logo、铭牌、文字、数字、表格或水印。背景通过图层方式与真实产品合成。

如果要生成应用场景，先生成合理的空场景，再把真实产品照片合成进去。若产品实际使用方式无法从资料确认，使用不展示危险动作的通用工业环境。

## 7. 主图逐张生产

五张主图必须有独立目标与构图：
- 01 核心成交：主标题、产品主体和核心卖点；
- 02 规格选型：真实SKU与规格矩阵；
- 03 细节结构：真实局部图和可验证说明；
- 04 应用场景：真实产品与合理场景合成；
- 05 下单须知：选型、物流、开票、批量采购和售后边界。

先完成 main_01 供用户审核。审核通过后，逐张完成 main_02 至 main_05。每张图单独生成、单独合成、单独导出、单独检查。不要先做五联图。

## 8. 八屏详情页

详情屏顺序：
1. 产品Hero；
2. 规格选型；
3. 外观与结构；
4. 参数表；
5. 应用场景；
6. 供货与物流；
7. 下单须知；
8. 客服咨询。

每屏独立排版，宽度1440px，建议高度1200–2200px。先输出8个独立PNG，再使用 compose_detail_long.py 无损拼接成长图。不能只交付一个缩略详情页。

## 9. 精确排版与合成

使用 scripts/render_layout.py 或等效图层工具完成背景、产品、细节、形状和文字合成。脚本配置必须明确图层位置、尺寸、字体、字号、颜色和对齐方式。

- 中文、型号、数字、单位、参数表和品牌文字由真实字体渲染；
- 产品图层使用真实图片，不重绘；
- 背景可以生成，但不能覆盖或改变产品；
- 文字溢出、字体缺失或图片放大过度时停止导出；
- 每次只处理一张完整画布，避免图像模型自动拼版。

## 10. 质检与打包

机器检查：文件存在、格式、尺寸、文件哈希、详情长图与八屏逐像素一致、ZIP完整性。

视觉检查：产品外观、铭牌、文字、参数、竞品版式相似程度、构图、对比度、手机可读性和场景安全性。

启用 REFERENCE LAYOUT LOCK 时，逐图与对应参考并排比对锁定项，在 VISUAL_QA 记录 REFERENCE_LAYOUT_QA、差异和返工结论。视觉结构明显不符即 FAIL，必须重做该张；未比对为 PENDING，两者都不得标为 FINAL 或整套通过。

事实检查：每个参数和卖点都有来源；竞品的未证实宣传不得沿用。

机器检查通过不等于视觉检查通过。qa_report.md 必须分别记录 MACHINE_QA 和 VISUAL_QA。所有必需文件存在并通过检查后，才可创建ZIP。

## 11. 上品资料

LISTING_PACK 根据当前商品事实生成标题、导购标题、属性、SKU、商家编码、价格核算和物流待确认事项。不得把其他型号的成本、吨位、链条、价格或运费套用过来。上架操作需要用户明确授权和适用工具。

## 失败处理

- 没有清晰产品原图：请求补图，不生成虚构产品；
- 无法透明抠图：使用原背景图或请求更合适角度；
- 没有中文字体：要求用户提供字体或安装可用中文字体，不输出乱码；
- 图像模型只返回拼版：拒绝作为成品，改为逐张生成；
- 详情长图不匹配八屏：重新拼接；
- 关键参数无来源：删除或标记待确认；
- 工具不支持独立文件：如实说明未完成，不提供虚假下载链接。
