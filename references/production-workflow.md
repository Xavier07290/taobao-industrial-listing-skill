# 通用工业品生产工作流

## 输入审查

1. 识别品牌、产品线、型号、真实来源；原图不足则标明哪些角度缺失。
2. 从厂家资料按产品分类抽取可信事实；保留原始单位、适用版本、规格差异及出处。
3. 判断哪些规格是现货、哪些为定制/选配，不把选配误写成标配。
4. 同类竞品图做**三栏表**：竞品表达 / 可验证的当前产品事实 / 可采用的原创营销表达。
5. 依商品特性选择卖点顺序：手拉/手扳葫芦关注额定载荷与高度；电动葫芦关注电压、控制、工作制；搬运车关注叉宽、叉长、轮型、承载；吸盘关注额定承载、适用工况与材料；钢丝绳/索具关注规格、材质、端头、使用限制。

## 校对优先级

铭牌、技术参数、规格与安全提醒属于高风险信息，必须首先核验。可见结构仅描述外观，不推断内部功能。竞品引用先判定当前型号有无证据。

## 图像制作

1. 规划5张主图：成交 / 规格 / 细节 / 场景 / 下单须知。
2. 从真实照片抠图，保持源像素产品结构和比例，保留原图备份。
3. 制作视觉框架和背景，真实产品以图层合成。
4. 从厂家数据生成准确、可读的参数表，避免让图像模型猜测中文和数字。
5. 分别导出5张独立3:4图、白底图、8屏详情图及拼接长图。
6. 和产品实物逐张比对，出现结构或铭牌错误则修正，不可修正时退回真实图片合成。

## 商品信息（LISTING_PACK）

- 标题：品牌 + 型号 + 真实品类名称 + 重要规格 + 搜索词。
- 导购标题：品牌 + 品类 + 简短选型点。
- 类目：以实际淘宝商品编辑器当前可选类目为准。
- SKU：按实际可售规格生成；吨位×高度只是部分葫芦的样例。
- 库存：填写已核实的仓库库存或供应商可履约数量，未知不能默认填20。
- 定价：按当前确认成本公式计算；运费、税费、售后和平台成本未知则标记待确认。
- 物流：按产品毛重、发货节点、地域和真实报价匹配模板，不使用占位费用上线。
- 正式上架需要用户明确授权；没有浏览器工具时，不声称已完成后台操作。

## QA

为每个商品输出 qa_report.md：产品外观、参数出处、竞品主张核验、中文文本、图像比例、SKU、物流状态以及所有待确认事项。不能用一张拼贴图冒充五张独立主图。

## V1.1：交付必须是真实独立高清图（优先级最高）

详见 [delivery-contract.md](delivery-contract.md)。用户认定的拼版只是视觉方向，不是最终商品原图。保留其黑红工业风、金属质感和营销版式，但要 **逐张独立创作与保存** 5张 `1440×1920` 主图，外加1张 `1440×1440` 白底图、8张宽1440的详情分屏、1张宽1440的长图。禁止从拼版缩略图裁切、拉伸放大。图像制作若无法生成独立成品，不能用简陋卡片/文档报告冒充成果。

只有所有15张文件实际落盘后，才可运行 `python scripts/verify_and_package.py outputs/<型号> --product <型号>`，并以校验通过的ZIP及各个单文件作为最终交付。无法落盘或无法导出时，优先单独生成每张图片，明确报告未完成资产，不得承诺不可验证的下载路径。
